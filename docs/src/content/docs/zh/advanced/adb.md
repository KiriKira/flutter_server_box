---
title: 通过 ADB 管理 Android
description: 配对、监控和管理本机或另一台 Android 手机
---

在 **添加／编辑服务器 → 连接** 中启用 **ADB**。下方会显示 ADB 配置区，
“使用配对码配对”入口位于设备地址、连接端口之前。无线调试（TLS）需要目标手机运行 Android 11 或更新版本。
Android 客户端内置 ADB 连接能力；Windows、Linux、macOS 客户端需要安装 platform-tools，
使 `adb` 位于 PATH 中。ADB 启用时使用目标手机的 Android shell 环境。

## 配对

连接另一台手机时，在目标机的开发者选项中开启无线调试，打开“使用配对码配对设备”，
然后点击 KiriBox 中的“使用配对码配对”，填写地址、配对端口和六位配对码。
目前支持配对码，不支持二维码配对。配对成功后仍需连接：连接端口取自无线调试主页面，
与配对端口不同。保存前可测试连接；Android 客户端还支持发现连接服务。

管理本机时选择“通过 ADB 管理本机”，点击“通过通知栏配对本机”。允许通知后打开系统的
无线调试配对码窗口，直接在通知栏输入配对码，然后返回 ServerBox 测试连接。
本机连接端口填 `0` 可自动发现。通知不可用时可用手动表单，必要时使用分屏。
配对任务两分钟后自动结束。

ADB 主机密钥仅保存在当前客户端，不随 ServerBox 分享、备份或同步传播；恢复设备记录后
可能需要重新配对。Android 可重新发现变化后的连接端口。传统 TCP ADB 是单独的高级选项，
无线调试不会主动退回该模式。

## 状态与终端

手机详情显示型号、Android/API 版本、安全补丁、执行身份、电池，以及能够采集到的 CPU、
内存、存储和网络读数。Android 版本与厂商限制不同，无法读取的指标不表示为零。
电池温度单独标注，避免与 CPU 温度混淆。

终端打开目标手机的交互式 ADB shell，直接输入 `pm list packages` 等命令即可，无需添加
`adb shell` 前缀。支持调整终端大小、Ctrl-C 和独立命令通道。退出终端只关闭当前 shell，
状态采集可以继续。手机不提供 systemd、Docker、防火墙和服务器用户管理页面。

Root 增强是可选项：在 Android 工具页申请后，由目标机已有的 root 管理器授权。
拒绝授权仍能使用基础监控。增强只影响状态采集，普通终端仍以 shell 身份打开；
可以在同一页停用，重连后需要重新申请。ServerBox 不负责安装 root，也不通过重启 adbd 提权。

## Android 工具

- 选择本地普通 APK 安装，分块上传后交给包管理器。Android 客户端会根据 APK 元数据核验
  安装后的包名和版本。断线时不自动重复安装。
- 搜索应用包、查看详情、启动、强制停止、卸载或清除数据。安装与应用管理目前面向 Android 用户 0。
- 浏览 shell 可访问目录，上传文件或下载。当前下载快捷入口限 32 MiB，APK 上传采用流式传输。
- 读取有限条数的最近 logcat 并导出、保存截图、重启目标机。

暂不包括 split APK、AAB、USB、屏幕控制和 root 私有目录浏览。
桌面端使用已安装的 adb server，只关闭自身通道，不结束共享 server。

## 本地 AI agent

全局 agent 将手机标为 Android（ADB），可查询状态、执行命令、读写可访问文件，
并通过 `android_device` 管理应用、日志、截图与 root 请求。
ADB 终端内的 agent 绑定该终端的手机连接；修改操作沿用现有审核设置。
配对码应填写在 App 配对流程中，无需发到对话里。
